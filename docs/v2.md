# gameofcreators.com: Supabase Database Schema & Feature Implementation Guide

## 📘 Platform Overview

gameofcreators.com is a contest-based content creation platform that connects brands (advertisers) and creators. Advertisers create promotional contests with a prize pool, and creators compete by submitting videos from their linked YouTube or Instagram accounts. Winners are chosen based on total views.

---

## ✅ Key Functional Behavior (To Be Implemented by Cursor)

### Step 1: Onboarding Flow

- Signup form captures: full_name, email, password, user_type, referral_code (optional), after signup if the refferal code is valid it is stored in db else we ignore this and user can later add valid refferal in settings add refferal section , if refferal added he can see refferal used - {referral_code}
- Send OTP (not link) to email after registration using Supabase email OTP
- OTP screen: user enters it → verified
- Then ask for `username` (must be unique)
- Once username submitted:
  - Store it in `users.username`
  - Set `referral_code = username`
  - Create relevant `creator_profiles` or `advertiser_profiles` row based on user_type
  - Award referral bonus (if referral_code was valid):
    - +100 coins to both the referrer & referred user

### Step 2: Admin Controls

- Creator and advertiser dashboard should show:
  - Coins balance
  - Withdrawable balance
  - Transaction history (money + coins)

### Step 3: UI Placement

- Top right corner or dashboard home: display `current coin balance`
- In settings, allow adding referral_code if missed at signup (only once)
- Referral Code generation is done after username confirmation

### Step 4: Submission Rules

- Only allow video from linked account (YouTube/Instagram)
- On contest end:
  - Leaderboard ranks users based on `views`
  - Manual review confirms rule-following
  - Prizes are credited post-approval

### Step 5: Subscriptions

- All users by default get `Free Plan you can reffer to subscriptionPlans.ts file for more details of the plan`
- Store full feature list in `subscription_plans.json_features`
- Restrict actions on contest creation based on active plan
- Allow Stripe/Razorpay-based plan upgrades
